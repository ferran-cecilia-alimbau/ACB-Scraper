1. Main Purpose: The primary goal of the project is to scrape detailed basketball match statistics from the ACB (Asociación de Clubes de Baloncesto - Spanish basketball league) website. It collects data for individual players, game information, and team totals.

2. Key Components & Responsibilities:

main.py: This is the main entry point of the application. It orchestrates the entire scraping process, including loading configuration, managing match IDs, initiating the scraping tasks, and saving the collected data.
scraper.py: Contains the core web scraping logic. It manages asynchronous HTTP requests (using aiohttp) to fetch web pages for matches and player profiles. The process_games function iterates through match IDs, and get_game_data handles the scraping for a single game.
parsers.py: This module is responsible for parsing the HTML content fetched by the scraper. It uses BeautifulSoup to extract specific data points like player statistics, game details (date, time, scores, referees), team names, team total statistics, and detailed player profile information (like height, birthplace, etc.).
get_match_ids/get_match_ids.py: A standalone script used to obtain a list of match IDs from the ACB website's calendar or results pages. It saves these IDs into match_ids.json.
http_client.py: Implements an asynchronous HTTP client with features like adaptive rate limiting and concurrency control to make requests respectfully and efficiently.
utils.py: Provides various utility functions for tasks such as cleaning data (e.g., percentages, height), normalizing text, and validating numbers.
constants.py: Centralizes constant values used throughout the project, such as base URLs, HTML selectors for parsing, column names for CSVs, and other fixed parameters.
logger.py: Configures the logging system for the application, allowing for detailed event recording during the scraping process.
Configuration Files:
config.json: Stores key configuration parameters for the scraper, including base URLs for fetching data, names of output files, retry attempt limits, delay between retries, and user-agent strings.
match_ids.json: Contains a list of match IDs that the scraper will process. This file is typically generated by the get_match_ids.py script.
Output CSV Files: The scraped data is stored in several CSV files:
estadisticas_todos_partidos.csv: Contains player statistics for all processed matches.
estadisticas_partido.csv: Stores detailed information for each individual match.
estadisticas_equipos_por_partido.csv: Contains aggregated statistics for each team per match.
perfiles_jugadores.csv: Stores detailed profile information for players.
3. Overall Workflow:

Obtain Match IDs: The process usually starts by running the get_match_ids.py script to populate match_ids.json with the IDs of the games to be scraped.
Load Configuration & Data: When main.py is executed, it loads settings from config.json and the list of match IDs from match_ids.json. It also loads any existing data from the output CSV files to avoid re-processing already scraped matches or player profiles.
Scrape Data: For each new match ID, main.py calls functions in scraper.py. The scraper makes asynchronous HTTP requests to the ACB website to fetch the HTML of the match statistics page.
Parse HTML: The fetched HTML is then passed to parsers.py, which extracts:
Game information (date, time, location, attendance, referees, scores).
Player statistics for both teams (points, rebounds, assists, minutes played, etc.).
Team total statistics.
Links to player profiles. If a player's profile hasn't been scraped before, it fetches and parses the player's individual page for more details (height, birth date, nationality).
Store Data: The extracted data is organized into pandas DataFrames and then appended to the respective CSV output files. The script ensures that columns are consistent and handles potential duplicates.
4. Key Features:

Asynchronous Operations: Uses asyncio and aiohttp for non-blocking HTTP requests, significantly speeding up the data collection process by allowing multiple pages to be fetched concurrently.
Configuration Management: Externalizes settings like URLs and file paths into config.json, making the scraper flexible and easier to configure.
Rate Limiting & Respectful Scraping: The http_client.py is designed to be respectful to the target server by implementing adaptive rate limiting and controlling concurrency.
Modularity: The code is organized into distinct modules with specific responsibilities (e.g., scraping, parsing, HTTP handling, utilities), which improves readability and maintainability.
Data Output: Saves data in the widely-used CSV format, making it easy to access and analyze with various tools.
Incremental Scraping: Loads existing data to avoid redundant scraping of matches or profiles already processed.
Error Handling & Logging: Implements error handling for network issues and parsing problems, and logs events for monitoring and debugging.
